# Докази внутрішнього пілота Thesica

Поточний перший етап — готова перша версія роботи для агенції.
Рішення: [бриф](../AGENT_SYNC.md).
Критерії віх: [роадмап M0–M3](../../THESICA-PLAN.md).
Операційний власник: Таня.

## Нові прогони

Кожне замовлення має окремий звіт за
[чинним шаблоном](../PHASE1_RUN_REPORT_TEMPLATE.md).
Вносити всі спроби, версію продукту, вхідні матеріали, змістовну оцінку,
точний DOCX, обидва результати Compilatio та no-rewrite.

- M1: короткі 10–20 сторінок; нові записи називати SHORT-001, SHORT-002 тощо.
  [SHORT-001](SHORT-001.md) для наявної роботи №5 підготовлений 07.09;
  READY / PENDING REAL RUN DATA, очікує явного старту Танею.
- M2: [RUN-001](RUN-001.md), [RUN-002](RUN-002.md), [RUN-003](RUN-003.md),
  повні 40–50 сторінок.
- M3: самостійні реальні замовлення; у звіті зазначати, чи можна використати
  вже виконаний M1/M2 як доказ операційної самостійності.

Порожні шаблони не є виконаними прогонами. Не створювати статус PASS
до перевірок. Не перезаписувати провал успіхом — лишати журнал спроб.

## Чинна якість

Зміст і джерела відповідають завданню; Compilatio similarity ≤10% та
AI ≤10% на одному фінальному DOCX; зміст не переписувала людина.
Методичка й PDF необов'язкові. Автоматичний сценарій без PDF має власні
докази в кожній хвилі, а не підміняється вручну зібраним пакетом.

Точні кількості й умови приймання містяться тільки в роадмапі.
Результати короткого тексту, старої моделі чи іншого файла не означають
готовності нової повної роботи.

## Історичні матеріали

CONTROL-RUN-A, CONTROL-RUN-B, CONTROL-RUNS-A-B, DOC5-CONTROL-RUN,
RESTART-DRILL, HANDOFF, MODEL-MATRIX-EXPERIMENT та HUMANIZATION-RESEARCH —
історичні результати або дослідження. Їхній зміст збережено без перепису.
Старі рекомендації й поняття human-minutes budget не є чинними правилами.

Вони корисні для діагностики, але не доводять поточний PASS.
Не публікувати приватні клієнтські дані або доступи до детекторів.
