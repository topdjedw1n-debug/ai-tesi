## Changes

1. **Persisted generation state.** An owner-scoped endpoint returns the latest
   full-document job, including status, progress, attempt count and stored
   failure. It returns null before a job exists and 404 for another owner's
   document. A newer section job cannot replace full-document progress.
   The UI reads it on entry and polls while active, alongside WebSocket updates.
   Socket disconnection is a connection notice, not a failed generation. Socket
   messages for other document IDs are ignored; terminal callbacks fire once.
2. **Actionable stop and new attempt.** A stored failure survives reload and
   explains the relevant remedy, with technical detail available for diagnosis.
   A temporary retry explains that completed sections are retained. An explicit
   new paid attempt requires acknowledgement that the cause was resolved and
   that previous parts/evidence will be replaced. This uses the existing owner
   generation endpoint; it does not grant the administrative retry permission.
3. **Connected operator screens.** Document responses include their associated
   case ID. Managers can move directly between work and checks and obtain the
   released DOCX from the case. Operational labels are Ukrainian and the shared
   workspace follows the existing light paper/green design. Failed case/list
   reads expose a refresh action instead of an endless spinner or false empty list.
4. **Consistent evidence and state.** The document quality card reads both
   Compilatio decisions from current server release gates. An old low percentage
   with a stale binding cannot display a pass. A successful release sets
   `delivery_status=ready` and `qa_status=passed`; revoking a prior release resets
   that QA approval. Client handoff is not asserted. The detail screen summarizes
   current gates rather than an obsolete independent status field. Existing
   administrative status editing is preserved.
5. **Rendered-page review.** New accepted content-review submissions require
   `reviewed_page_count` (positive integer, at most the existing 1000-page bound),
   on the server as well as in the form. It is saved in the artifact-bound
   `content_reviewed` event and shown on later reads. Rejected/rewritten reviews
   may omit it. The UI asks the manager to open the unchanged formatted DOCX in
   Word/LibreOffice and compare it with the agreed target. This is a human check,
   not word-count pagination, automatic layout verification or a newly invented
   page-tolerance rule. Historical evidence is not rewritten or backfilled.
