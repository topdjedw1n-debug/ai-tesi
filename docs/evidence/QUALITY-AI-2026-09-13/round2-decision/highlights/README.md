# Що саме підкреслює Compilatio в наших текстах — розбір шести детальних звітів (13.09.2026, Fable, без витрат)

**Метод.** Підкреслення у PDF-звітах Compilatio Studium — тонкі кольорові прямокутники під рядками тексту (розділ «Punti di interesse / Points of interest, section 3/3»). [extract_highlights.py](extract_highlights.py) зіставляє їх зі словами (PyMuPDF): блакитний колір `(0.0, 0.75, 1.0)` — «стилістично близько до AI», коричневий — «текст у лапках». [analyze_highlights.py](analyze_highlights.py) відновлює абзаци й розділи (за заголовками з планів робіт), ділить на речення й рахує частку підкреслених слів за ознаками речень. Файли `*.lines.json` — рядки з позначками слів, `*.analysis.json` — підсумки, [summary.json](summary.json) — зведення.

**Перевірка методу.** Частка підкреслених слів, порахована з PDF, збігається зі звітами Compilatio: A 14,25 % (звіт 14 %), B 33,2 % (33 %), C 35,5 % (35 %), B-V0a 28,2 % (28 %), B-V0b 39,0 % (39 %), B-V1a 29,8 % (30 %). Коричневий колір ≈ 1 % = «testi tra virgolette» у звітах.

- **Формули обмежень і мета-коментар про уривки детектор не підкреслює** (0 % у чотирьох файлах із п'яти, де вони є). Раніша оцінка «16–21 % позначеного — формули» з ручного читання не підтверджується підрахунком; прибирання формул (V1a) і не могло допомогти — це вже було видно у результаті 30 %.

Файл із найщільнішою опорою на джерела (A) має найнижчий показник, файл із найрідшою (V0b) — найвищий. Шість точок — не доказ, але напрямок однаковий з таблицею вище. ## 3. Підкреслення не прив'язані до конкретних розділів — вони «плавають» між генераціями

Частка підкреслених слів по одних і тих самих розділах B у трьох незалежних генераціях (та сама інструкція у V0a/V0b):

| Розділ | B (серія) | B-V0a | B-V0b | B-V1a |
|---|---:|---:|---:|---:|
| Introduzione | 44 % | 36 % | 0 % | 0 % |
| La riforma del Jobs Act | 59 % | 5 % | 76 % | 58 % |
| Obblighi del datore di lavoro | 25 % | 0 % | 63 % | 21 % |
| L'utilizzabilità dei dati raccolti | 36 % | 46 % | 85 % | 25 % |
| Conclusioni | 63 % | 0 % | 40 % | 41 % |

Той самий розділ за тим самим брифом і тими самими доказами отримує від 0 % до 76 %. Отже, детектор не реагує на щось стале в темі чи структурі розділу: наша проза лежить біля межі його класифікатора, і рішення «AI / не AI» для уривка близьке до випадкового з імовірністю ≈0,3–0,4. Позиція абзацу в розділі (перший/останній) теж не має стійкого ефекту.

## 4. Що з цього випливає для «кореня»

1. Шукати й забороняти окремі фрази — хибний шлях: підкреслюється не фраза, а **загальна проза без опори**. Список «заборонених патернів» ефекту не дасть (V1a це вже показав).
2. Спосіб зрушити показник, який узгоджується з даними і не залежить від того, як детектор оновиться наступного тижня, — писати **з опорою**: кожен змістовний абзац несе конкретику з джерел (норма, рішення, число, позиція автора, коротка цитата), а загальні пояснення й переходи зведені до мінімуму. Це водночас критерій якості роботи, а не трюк проти детектора.
3. Межа цього важеля за нинішніми джерелами: якщо речення з опорою підкреслюються ≈20 %, а без опори ≈40 % (право), то навіть подвоєння частки речень з опорою (з 20 до 60 %) зсуне файл лише з ≈36 % до ≈28 %. Щоб дійти до 10 %, має впасти й підкресленість самих речень з опорою (як в A: 9 %). Це вказує на **матеріал**: з анотацій модель не може зробити 400–600 слів конкретики на розділ, тому дописує загальне. Повні тексти або сторінкові уривки джерел (S2) — корінь глибший за інструкцію.
4. Два дешеві калібрування лишаються потрібними: повторний скан незміненого файла (шум детектора) і скан справжньої людської tesi у тому ж Studium (чи планка 10 % взагалі досяжна для людини в цьому жанрі).

**Межі розбору.** Ознаки речень — регулярні вирази, без синтаксичного аналізу; шість файлів однієї моделі; частки на маленьких групах речень (у дужках) нестійкі. Це напрямок для наступного платного кроку, не доведений рецепт.
