# Суд моделі на документ: калібрувальний прохід (17.09.2026, фаундер: «Так, 1 і повтор брифу»)

**Що перевірялося.** Чи може одна дешева модельна відповідь на документ відрізнити повний текст «про тему роботи» від тексту тієї самої галузі про інше питання — там, де лексичні ворота цього не роблять ([калібрування якорів](../anchors-2026-09-17/README.md)). Матеріал: 41 документ — усі 33 повні тексти чотирьох записів (A2 9, E2 6, BIO 10, PSY 8) і 8 копій психології ([зонд](../copies-2026-09-17/README.md)). Мітки: **OFF** = 11 відомих чужих; **ON** = решта записаних (22, серед них дотичні); **ON-copy** = 8 копій. Скрипт [calibrate.py](calibrate.py): тема, вимоги менеджера, вузли S1 з двомовними термінами, назва/анотація, три уривки з локаторами (перший із якорем теми; з найбільшою кількістю різних якорів; найкращий з останньої третини) → JSON `verdict / population_match / scope_ids / reason`. Витрачено **$0,75** (стеля $1): Haiku 4.5 ×2 ($0,115 + $0,118), Sonnet 5 ($0,52).

**Дві версії критерію.** v1 («та сама популяція і те саме коло питань») — Haiku відсіяв 11/11 чужих, але й 13/22 своїх і 3/8 копій, зокрема «Self-comparison with influencers» (студенти, не підлітки) — надто суворо ([haiku.txt](haiku.txt)). v2 (вирішує **явище і коло питань**, а не галузь чи вибірка; інша вибірка → `allow` з `population_match: false`) — [haiku-v2.txt](haiku-v2.txt), [sonnet-v2.txt](sonnet-v2.txt) (у Sonnet 13 відповідей обрізано `max_tokens=300` — вердикт відновлено з початку JSON, позначено `*`; повні prompt/answer у [haiku-v2.json](haiku-v2.json), [sonnet-v2.json](sonnet-v2.json)).

Відхилені «свої» — з причинами, які збігаються в обох моделей: е-комерція й експорт фірм (A2), краудсорсинг у маркетинговій комунікації (A2), гнучкість МСП у VUCA (A2), бізнес-модель стартапу (A2, Haiku), моделі дефолту за територією (E2), загальний огляд фінтех-технологій (E2), загальний огляд досліджень соцмереж (PSY), інтерпретація антибіотикограм і синергія глікопептидів (BIO, Haiku). Це тексти тієї самої галузі про інше питання, які попередні прогони використовували як матеріал; редактор назвав би їх натяжкою, але їхні сторінки були в файлах 3/3 і <1 %.

**За правилом Grok (смуга частки [0,5; 0,9), ≤ 8 викликів, найнижча частка першою; ≥ 0,9 і < 0,5 — без виклику), Haiku v2:** PSY — усі 5 чужих у смузі → reject, свої (≥ 0,9) без виклику, копії allow (крім огляду про ізоляцію); E2 — Islamic Finance і Understanding Financial Crises (смуга) → reject, модель дефолту → reject, FinTech review (0,97) без виклику; BIO — у смузі 5 своїх: 4 allow, 1 reject (синергія глікопептидів, 18 вікон); A2 — у смузі 5 своїх: 1 allow, 4 reject (експорт/е-комерція, краудсорсинг, VUCA, стартап). Умова Grok «не зачепити свої тексти біології» виконана з одним дрібним винятком; ціна для економіки-1 — чотири дотичні тексти.

## Рішення й реалізація (коміт 3)

`app/services/topic_judgment.py`: кандидати = отримані повні тексти (не PDF менеджера) з часткою у [0,5; 0,9), найнижча першою, ≤ 8; один записаний виклик `model_call(..., model="claude-haiku-4-5-20251001", purpose="S2_judge")` (≈ $0,003 на документ, облік у витратах роботи, replay без мережі); `reject` → уривок перебудовано з анотації, рівень доказу назад до `abstract`, `full_text_usable` = False (сторінок не отримує жоден шлях: заплановані, додані, запасний уривок, перевірка плану); `allow` / `uncertain` / нечитабельна відповідь / помилка провайдера — нічого не змінюється; подія `executor_topic_judgment` з вердиктами й причинами; попередження менеджеру `source_full_text_off_topic` словами. Тести: `tests/test_topic_judgment.py` (уривки, парсер обрізаних відповідей, смуга й стеля, ефект reject, помилка провайдера). Не змінено: писар, план, рамка, модель письма.

Не доведено: AI-відсотки після воріт — їх дасть повтор брифу психології на цій версії.
