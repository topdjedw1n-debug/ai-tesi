## Outcome and boundary

The existing initial retrieval, section candidate merge, preflight, persistence
and frozen-pack recovery were inspected rather than implemented again. Three
observed gaps were fixed with changes to two backend modules. No schema change,
production write, deployment, paid generation or message to Tanya occurred.
No live document or saved outline was changed.

This is readiness evidence for M0, **not a completed work or M1 PASS**. The
public canary uses the selected nursing topic, a manually prepared English
translation and two representative section scopes. It does not reproduce the
saved four-chapter outline, execute the LLM translator/writer, produce a DOCX,
check Compilatio or measure manager time. Those boundaries are explicit in its
inputs. Source existence is not proof of the quality of the final thesis.

## Observed defects and minimal changes

1. **Initial provider outages were swallowed.** Real Crossref/OpenAlex adapters
   return an empty list on HTTP failure unless asked to raise. The initial
   pipeline wrapper did not request that behavior, so `provider_errors` was
   empty despite HTTP 503. The wrapper now enables it by default; the builder
   still retains partial results and captures errors in the returned pack.
   Existing pipeline checks can now distinguish an outage from a clean but
   insufficient search before section writing. An HTTP-transport regression
   exercises the actual adapters and builder, not a preconstructed error pack.
2. **An unfrozen retry could reuse an incomplete list indefinitely.** Persisted
   provisional rows lose provider-error context. A nonempty weak list was
   reloaded instead of refreshing retrieval; a context-only list then failed
   permanently. Under the preflight profile, an attempt without a frozen digest
   or completed sections now builds fresh candidates. Frozen resume still uses
   the original persisted keys/proofs/digest and does not retrieve or reverify.
   Legacy flag-off resume behavior is retained. Real SQLite round-trip tests
   cover both a context-only list and a partially citable list, followed by a
   verified 24-source pack reaching the writer and export stub.
3. **Existence verification admitted the wrong study population.** The first
   live canary returned 24 verified publications, but three were about foals,
   domestic mammals and rats. Those are genuine sources with misleading
   keyword overlap for this nursing topic. Before scoring/reserve selection,
   a bounded title-based suitability filter now excludes explicit animal study
   populations for nursing/midwifery scopes. An explicit animal/veterinary topic
   or section keeps such sources eligible. Tests retain clinical papers about
   emu-oil lotion and rat-bite patient care; arbitrary animal references in an
   abstract are not a reason to exclude a source. This is a targeted relevance
   safeguard, not a universal classifier or a new supported-topic promise.

The insufficient-source message now says automatic selection needs review and
that PDFs are optional. It no longer makes managers supply PDFs as the remedy.
Preparation/translation/outline may still have cost; no claim is made that all
pre-section failures cost zero.

## Public-metadata canary

Both searches used current public Crossref/OpenAlex results and fresh
`CitationVerifier(cache_enabled=False)` lookups, without production credentials,
uploaded PDFs, database records or LLM calls. Release-profile bounds were
target 24, minimum 18, reserve 48 and relevance threshold 0.35.

| Observation | Before relevance fix, 13:59:23–13:59:49 UTC | After fix, 14:07:42–14:08:07 UTC |
|---|---|---|
| Initial citable / context | 24 / 0 | 24 / 0 |
| Retrieval provider errors | 0 | 0 |
| Candidates after section merge | 48; initial keys retained | 48; initial keys retained |
| Final verified sources | 24 | 24 |
| Explicit unrelated animal-population papers in final pack | 3 | 0 |
| Page-2 top-up needed | No | No |
| Metadata rejections | 1 not found; 1 mismatch | 1 not found; 1 mismatch |

The three removed records were replaced by sources about cord-clamping and
neonatal transition, perinatal viability, and the neonatal nurse's role in risk
management. The initial metadata-only `pass` is preserved in raw evidence and
is explicitly **not** treated as passing the subsequent relevance review.

The verifier also logged a Crossref HTTP 301 and a Semantic Scholar HTTP 429
during its cascade. These did not leave the final pack short; they are not
hidden behind the zero retrieval-error count above. No claim is made that
every provider request succeeded or that every retrieved candidate verified.

[The exact canary runner](M0-04-2026-09-05-canary.py) can be replayed from the API
directory with `PYTHONPATH` pointing there, `ENV_FILE=/dev/null`, test-only
`SECRET_KEY`/`JWT_SECRET`, `ENVIRONMENT=test` and an in-memory SQLite URL. Pass an
output JSON path as its sole argument. The run has a 300-second bound. Actual
external metadata may change; the original responses are retained in JSON.
