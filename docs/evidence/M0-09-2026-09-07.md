## Результат для менеджера

За тимчасового збою пошуку система повторює запит і добирає джерела з
наступних сторінок. Зіпсований план виправляється до написання роботи.
Обрізана або порожня відповідь моделі не зберігається як готовий розділ:
система повторює її з достатнім обсягом відповіді й обмеженим очікуванням.
Внутрішній акаунт з уже дозволеними необмеженими генераціями не зупиняється
через довільну стелю у 100 перевірок тверджень. Усі фактичні витрати й
перевірки продовжують обліковуватися.

Три тестові роботи з реальними зверненнями до моделей і пошукових сервісів
дійшли до DOCX. Одна завершилася після навмисного перезапуску API, зі
збереженням того самого job і всіх уже написаних розділів. До цього
перший освітній прогін виявив ще один дефект; його FAIL збережено, причину
виправлено, новий освітній прогін завершився одним запуском.

## Конкретні причини та виправлення

| Причина зупинки | Виправлення і перевірка |
|---|---|
| 429, 5xx або тимчасовий розрив запиту до scholarly API | До трьох HTTP-спроб з паузами 2/4 с; постійні 4xx не повторюються. Пошкоджений окремий запис більше не відкидає придатні сусідні. Корпоративний автор Crossref підтримується. OpenAlex отримує налаштований ключ у заголовку, без ключа в URL. Регресії для кожного провайдера. |
| На першій сторінці замало придатних джерел | Початковий і фінальний добір використовують сторінки 2/3 до остаточної зупинки; попередні джерела збережені. Ціль 24, мінімум 18, поріг релевантності та верифікація не знижені. Два повні сценарії завершилися за один job без PDF. Наявні dedup і вибір багатших метаданих не переписували. |
| JSON плану порожній, пошкоджений або містить надто великий розділ | До трьох спроб тієї самої моделі до збереження плану. Нові розділи понад 3000 слів розбиваються зі збереженням загального запитаного обсягу. Придатні старі плани лишаються; старі необов'язкові `null`/0 цілі не ламають відновлення. Завершені розділи не отримують нову структуру мовчки. |
| Відповідь обрізана лімітом, порожня або не встигає за початковий timeout | Початковий обсяг відповіді відповідає цілі розділу; обрізаний результат повторюється до обмеженого максимуму 16000 токенів. Очікування масштабується 180–600 с. Вкладені повтори SDK вимкнені, клієнти закриваються, використання кожної спроби записується. Для legacy Claude 3 збережено попередню межу 4000. Чотири повні сценарії timeout/429/truncation/empty завершилися за один worker attempt. |
| Внутрішня робота переривається на 101-й перевірці | Для вже дозволеного `UNLIMITED_GENERATION_USER_IDS=[1]` довільна стеля знята; атомарний лічильник зберігається між відновленнями. Звичайні акаунти мають свій ліміт. Штучна робота: 132 перевірки; реальні: 101 та 156. |
| Змістовний розділ із цитуванням відхилявся лише через відсутність чисел | Евристика числової конкретики може поступитися увімкненій блокувальній перевірці тверджень лише за **фактично виконаної** семантичної перевірки. Самого прапорця недостатньо: нульовий бюджет або відсутність доступного abstract не дають експорту описового розділу без числової конкретики. Цитування, джерела й решта перевірок збережені. Негативні інтегровані регресії та новий реальний освітній прогін. |

Повна відсутність релевантної літератури після обмеженого добору залишається
зрозумілою зупинкою; джерела не вигадуються. Необмежені цикли повторів і
прихована заміна моделі не додані. Писар залишається `claude-opus-4-8`,
fallback і humanizer вимкнені.

Разом облік застосунку — **497 cents**, включно з невдалим прогоном;
це не незалежна звірка рахунку провайдерів. Під час прогонів відбувалися
справжні Crossref/Semantic Scholar 429 та обрізання відповідей; вони дали
матеріал для перевірки відновлення й виправлення початкового обсягу відповіді.

Прогони виконувалися на підготовленому кандидатові під час внесення
виправлень. Не стверджуємо, що кожний їхній крок виконав саме фінальний
`db9f887`. Початкові хеші коду збережені. Остаточне посилення семантичної
перевірки звірено з усіма завершеними розділами; фінальна версія окремо
пройшла всю матрицю 9/9, API-тести й тести точного production-образу.

DOCX 11/13/14: ZIP без пошкоджень, відкриваються парсером Word, внутрішні
невирішені citation markers відсутні; скачані байти відповідають SHA-256 у
базі. SHA-256, розміри, час і докази розділів — у JSON. Три попередні розділи
job13 після restart мають ті самі ID та MD5. Файли й результати збережені
локально в `.scratch/m0-09/`; приватні ключі там не зберігаються.

Запитані 10/18/20 сторінок не є заміром сторінок готового Word-файла.
Compilatio, приймання змісту/джерел/оформлення й no-rewrite тут **не виконані**.
Діагностичні GPTZero/Copyscape не замінюють Compilatio. Ці три технічні
завершення не зараховуються як три послідовні M1 PASS.
