## Межа доказу

Основна перевірка виконана в окремому checkout і Docker-проєкті:
справжні HTTP API, браузер, PostgreSQL 15, Redis, MinIO, worker, блокування
рядків, збереження розділів, створення DOCX і правила видачі. Платні ключі
та робочі дані не використовувалися. Зовнішні відповіді писаря, джерел,
граматики й детекторів контрольовані та **штучні**. Звіти з позначкою QA
не є справжнім Compilatio, прийманням змісту або підтвердженням 18 сторінок.

Результат — перевірена технічна поведінка перелічених сценаріїв, а не
гарантія відсутності будь-яких майбутніх збоїв зовнішніх сервісів. M1/M3
потребують реального змісту, джерел, того самого DOCX у Compilatio та
самостійного приймання менеджером. Таню не залучали до пошуку цих дефектів
і повідомлень їй не надсилали.

## Перевірені сценарії

- Неправильний пароль; порожня/коротка або очищена тема; від'ємні,
  нульові, дробові й надмірні сторінки; неправильні тип, стиль, модель;
  неіснуючий документ. Дані відхиляються до запуску.
- Непридатна методичка: upload 422, технічна чернетка прибрана через
  штатний DELETE, тема й вимоги лишилися у формі; генерації немає.
- Reload, вимкнення мережі та повернення, повне закриття й відкриття
  браузера, відновлення простроченої сесії — та сама серверна задача.
- Два одночасні старти дають одну активну задачу. Реальний HTTP-ліміт
  5/hour окремо повернув 429 без додаткової задачі; лише після цього його
  вимкнули в ізольованому стенді для серії випробувань.
- Скасування в черзі, під час написання та під час upload; reload після
  скасування не запускає нову спробу, застарілий виконавець не зберігає
  результат. Пізній файл не стає доступним і прибирається зі сховища.
- Graceful restart і SIGKILL worker після першого розділу: той самий job,
  збережений розділ має той самий ID/хеш, по одному запису кожного розділу.
- Вимкнення Redis, MinIO та PostgreSQL: відновлення з наявних розділів,
  без хибної видачі незавершеного файла.
- Timeout, 429, зіпсований outline, порожня відповідь писаря, замало
  джерел і відмова провайдера джерел: обмежені спроби, явна причина,
  жодного доступного DOCX з неповною роботою.
- Внутрішній DOCX, звіт, 22%, 10%/10% без огляду, повний комплект доказів,
  видача точних байтів, відкликання старого посилання після переписування.
  Неправильний файл звіту, чужий/неіснуючий report ID або інший fingerprint
  не проходять. Окремо весь позитивний шлях звіт → два показники → огляд
  → reload → дозвіл пройдено через справжні браузерні форми.
- 54 твердження при ліміті 50: після виправлення одна зупинка
  `failed_quality` без `MissingGreenlet`; при ліміті 100 — усі 54 перевірено,
  6 розділів і справжній DOCX. Необов'язкова діагностика не скасовує
  дозволений повтор після зауваження панелі.

Точні IDs, відповіді, хеші та результати — у JSON. Усі QA IDs належать
окремій базі й не є номерами реальних замовлень.

## Фактична перша спроба на робочому сервері

14:06:34–14:16:46 UTC, `failed`, 3 внутрішні спроби; 5 збережених розділів

188248 токенів, `cost_cents=131`; це дані застосунку, не незалежна звірка
рахунку провайдера. Особу, яка натиснула старт, цими даними не встановлено.

Початкова помилка — вичерпаний ресурс перевірки тверджень та програмний
збій ISSUE-008. Нестача кредитів Copyscape також зафіксована, але цей
діагностичний сервіс не є умовою приймання замість Compilatio (ISSUE-007).
Реальний результат збережено як FAIL у SHORT-001; його не стирали,
не перезапускали й не зараховували як готову роботу.

## Незалежний перегляд і перевірки

Чотири незалежні перегляди Claude CLI: початкові 6 виправлень,
видача/скасування коміту, збій ліміту та останнє уточнення відображення.
Підтверджених блокерів після розбору немає. Зауваження про пул MinIO/5xx,
login constant, гонку коміту й видалення, невідому причину failure,
необов’язкові claim-перевірки та стан до першого розділу враховано.
API деталей завжди формує масив sections; завершений статус і правила
видачі не змінені. Старі очікування діагностичних гейтів змінено навмисно;
обов’язкові негативні гейти лишилися перевіреними.

Фінально: **1166 API passed / 10 skipped; 204 web passed / 1 skipped**,
30 web suites; 2 справжні PostgreSQL-перевірки конкурентної видачі;
**123 passed у точному amd64 API-образі** без мережі. API-код b8b3315
побайтно тотожний перевіреному 915cb09, тому після суто web-уточнення
серверний набір не повторювали. Web lint/typecheck і production build
пройшли; Ruff passed. Mypy: 354 наявні помилки проти тих самих 354 у базі,
нових немає. Загальний CI не оголошується безумовно зеленим.

Помилки підготовки стенду відокремлені від дефектів продукту: спочатку
не створили MinIO bucket; перший Docker mount мав неправильну глибину
для тесту runtime contract; native QA session згодом протермінувалась;
кілька локаторів/очікувань уточнено за реальною схемою. Для тестів
серверного образу також виправлено неробочу директорію non-root та
додано до read-only test mount обидва файли CI/deploy workflow з того
самого коміту; вони не входять до runtime payload.
Вони не приховані й не зараховані як успішні продуктові перевірки.
