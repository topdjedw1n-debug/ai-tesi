## Proven defects

1. **Medium. Release-gate reads now take a row lock and hash report bytes from storage on every read.** `apps/api/app/services/production_case_service.py`, `get_release_gates` was switched to `get_case_and_document_for_update`, and the new `else:` branch calls `_checked_report`, which runs `StorageService().get_file_sha256` on the stored report for each detector gate. Trigger: any GET of release gates, every secure download through `_require_released_production_case` in `documents.py`, the tail of `record_content_review`, the admin detail page `load`, and the new `DocumentQualityEvidence` call to `getReleaseGates` on every dashboard document view for the operator. Impact: two full report downloads of up to 20 MB per read, with the case and document rows locked for the duration of MinIO I/O. Concurrent manager actions on the case serialize behind viewers and download attempts, and a slow MinIO stalls writers. Minimal correction: use the non-locking `get_case` plus `_get_document` in `get_release_gates`, since every mutating caller already holds the lock. Keep byte verification where it matters: at `record_detector_result` and `download_detector_report`, which already do it, and add a single verification in `release_case`. On read, keep the binding and existence checks without re-hashing.

2. **Low. The status poll overwrites WebSocket detail every 3 seconds and can move the bar backwards.** `apps/web/components/GenerationProgress.tsx`, poll effect. A polled `running` job is fed to `applyMessage` as `progress_update` with no `current_section` or `estimated_time`, and that branch replaces the whole state. Trigger: WS delivers a section name, then the next poll tick clears it. DB progress may also lag WS progress. Minimal correction: for polled results use a functional merge that preserves `currentSection` and `estimatedTime`, and only lower `progress` when the socket is disconnected.

3. **Low. Saving one evidence form discards unsaved input in the others.** `apps/web/app/admin/production-cases/[id]/page.tsx`. `onSaved` calls `load`, which sets `loading` true, and the early `if (loading)` return unmounts `ReleaseEvidenceForms`. Trigger: manager fills both detector forms, saves the similarity result, and the AI form and the selected report reset. Minimal correction: render the spinner only when `productionCase` is null and refresh in place.

4. **Low. A download attempt on a not-yet-released case now writes to the database.** `apps/api/app/api/v1/endpoints/documents.py`, `_require_released_production_case`. The added `or production_case.release_status != "released"` routes unreleased cases through `revoke_release` and a commit, which resets `delivery_status` and `released_at` from a read path. Minimal correction: call `revoke_release` only when the case is currently released; otherwise raise directly.

## Needs context before sign-off, ordered by potential impact

1. **Report upload through `apiClient.post` with `FormData` is unverified.** `apps/web/lib/api/admin.ts`, `uploadDetectorReport`. Every web test mocks `adminApiClient`, so the real `post` never sees a `FormData` body. If `post` JSON-stringifies the body or `createHeaders` forces `Content-Type: application/json`, the endpoint returns 422 in a browser and no release can be recorded. Please confirm `post` special-cases `FormData`, or add one unmocked test against `apiClient.post`.

2. **Operators have no UI path to create a case unless generation auto-creates one.** `apps/web/app/admin/production-cases/page.tsx` hides the create form in the operator view and states the case is created at first generation start. `TaskContractPanel` repeats that claim. Nothing in this delta creates a `ProductionCase` on generation start, and the existing test about a racing case losing to a job implies cases are created before generation. If the base does not auto-create, manager1 cannot reach the release flow from the browser at all. Verify `generate_document_async` or the job creates the case; otherwise show the create form to operators, which the API already permits for owned documents, and fix the copy.

3. **The operator's internal DOCX download is not exercised end to end.** `apps/api/tests/test_production_operator_access.py` only asserts `token=` appears in the URL. The redeem path in `download_document_secure` now reads the full object and compares against `expected_sha256`, whose origin for the internal review scope is outside the diff. `test_document_download.py` only patched the client-delivery test, which suggests no test streams the internal scope. Add a test that follows the URL and checks the bytes.

4. **Operators may be able to write status fields via PATCH.** `apps/api/app/api/v1/endpoints/production_cases.py`, `check_operator_assignments` restricts only `manager_id` and `editor_id`. If `ProductionCaseUpdate` accepts `release_status`, `qa_status`, `editorial_status` or `delivery_status`, an operator can set them directly. Release and downloads stay fail-closed because gates recompute from evidence, but the list and dashboard statuses could be spoofed and `delivery_status` is not gate-derived. Confirm the schema and restrict those fields for non-admins if present.

5. **`raise_on_provider_error=True` now applies to every `_build_source_pack` call.** `apps/api/app/services/background_jobs.py`. This includes the post-outline rebuild. Confirm the downstream path does not turn a partial provider error on an otherwise sufficient pack into a retry or failure, and that the retry path is bounded by `max_attempts`.

6. **Preflight-on resume no longer loads persisted rows unless frozen.** Same file. A job in flight at deploy time whose pack rows were persisted but never marked frozen would have its pack rebuilt with new citation keys after sections were written, and would then fail the unresolved-marker check at export. The delta has a flag-off resume test only. Confirm every preflight-passed pack is frozen before the first section is written, and that no such jobs are live during rollout.

7. **Retry label semantics depend on `attempt_count` initial value.** `GenerationProgress.tsx` labels `queued` with `attempt_count > 0` as a retry. If the worker sets `attempt_count` to 1 on first lease and returns to `queued`, every fresh job shows "Повторна спроба".

8. **Failure-path signature.** `upload_detector_report` calls `storage.delete_file(path, silent=True)` inside an `except`. Tests replace `delete_file` with an `AsyncMock`, so an incompatible signature would raise `TypeError` and mask the original error. Confirm the keyword exists.

9. **`delivery_status` moved from `delivered` to `ready` on release.** Anything outside the delta that reads `delivered`, such as the Telegram journal from the previous commit, should be checked.

## Remaining concrete defects

1. **Low, test regression. The foreign-case PATCH assertion now fails.** In `apps/api/app/api/v1/endpoints/production_cases.py`, `update_production_case` runs the new administrative-field check before the service resolves the case. In `apps/api/tests/test_production_operator_access.py`, `test_foreign_documents_cases_and_assignments_are_inaccessible` patches the foreign case with `{"intake_status": "ready"}` and asserts 404. With the current endpoint, `model_fields_set` minus the allowed set is non-empty for a non-admin, so the request returns 403 before any lookup. The behavior itself is acceptable, since a uniform 403 leaks nothing about existence. The assertion is wrong, and the pending final run should show it. Minimal fix: change that payload to an allowed field such as `requirements_text` so the 404 ownership assertion still holds, or move the field check after `service.update_case` resolves the case if 404-first semantics are wanted.

2. **Unverified, conditional deadlock. Lock acquisition order in `get_case_and_document_for_update` is still not in the supplied context.** The worker comment fixes the global order as Job, then Document, then ProductionCase, and `generate.py` follows it: document lock first, then `ProductionCase ... with_for_update()`. If the helper locks the case row first and the document row second, this interleaving deadlocks:

```
T1 generate_document_async:  SELECT document d FOR UPDATE            -> holds d
T2 get_release_gates:        SELECT production_case c FOR UPDATE     -> holds c
T1:                          SELECT production_case c FOR UPDATE     -> waits on T2
T2:                          SELECT document d FOR UPDATE            -> waits on T1
```

Postgres aborts one transaction after `deadlock_timeout` with 40P01, so the symptom is a 500 on a gate read or a generation start for the same document, not a hang. If the helper acquires Document before ProductionCase, there is no defect and the retained row lock plus report re-hash stands as the accepted correctness-first tradeoff. I am not asking to remove validation. Confirm the order in the helper body.

## Disposition of earlier findings

Proven defects:

- **Defect 1, lock plus report hash on every gate read.** Accepted by owner as a bounded correctness tradeoff. Not a defect on its own. The only residual risk is the lock order above.
- **Defect 2, poll overwrote socket detail.** Fixed. Polled results carry `persisted_poll`, which preserves section and estimate, and `preserve_live_progress` takes the max while connected. The parametrized merge test covers both connection states.
- **Defect 3, saving one form reset the other.** Fixed. The spinner renders only when no case is loaded, and the forms are keyed on the DOCX fingerprint so input survives same-artifact refreshes and resets on a new artifact. Both branches are tested.
- **Defect 4, unreleased download wrote to the database.** Fixed. Unreleased cases are rejected before `get_release_gates`, and `revoke_release` plus commit run only when the case is currently released.

Needs-context items:

- **1, FormData upload.** Resolved. `apiClient.post` drops the JSON content type for FormData, and the unmocked fetch-spy test asserts the body and headers.
- **2, operator case creation.** Resolved. `generate_document_async` creates the case under the document lock before the job when none exists. Residual assumption: the auto-created case has no `manager_id`, so operator visibility depends on `owner_user_id` scoping by client or document owner, which is what I traced in the earlier pass.
- **3, internal DOCX end to end.** Resolved. The operator test follows the tokenized URL, compares bytes, and gets 409 when the stored hash diverges.
- **4, operator status writes.** Resolved. The schema forbids unknown fields, so `release_status` and `delivery_status` are unreachable, and the endpoint rejects the eight administrative fields for non-admins with tests for each. See defect 1 above for the test ordering side effect.
- **5, provider errors with raise enabled.** Resolved. The builder catches provider exceptions into `provider_errors`. Insufficient packs with transient errors raise a retryable RuntimeError, retries are bounded by `max_attempts`, and sufficient packs proceed.
- **6, preflight resume.** Resolved. Rows and lease digest commit atomically in `persist_generation_source_pack`, sections written without a digest fail closed, and the live read shows no in-flight jobs.
- **7, retry label.** Resolved. `attempt_count` increments only on claim, so a fresh queued job shows "В черзі" and a re-queued one shows the retry label.
- **8, `delete_file(silent=True)`.** Resolved. The keyword exists.
- **9, `delivered` consumers.** Resolved by owner call-site check. The Telegram "delivered" is transport acknowledgement only.

Deploy script and its four fake-command tests read consistently. The overlay is retained on every compose action, a bot without config stops before any mutation, and an invalid compose stops after the single `config --quiet` call.

## Final resolution

Model(s): claude-haiku-4-5-20251001, claude-fable-5-1

**Verdict: both conditions are satisfied. Sign-off is unconditional within the supplied scope.**

**Condition 1, foreign-case PATCH 404.** Confirmed by the dependency body. For a non-admin operator, `require_production_permission` resolves the path `case_id` to its `document_id` and calls `require_owned_document`, which raises 404 when the document is not owned. FastAPI evaluates this dependency before the handler runs, so the endpoint's administrative-field check is never reached for a foreign case. My prior finding described the handler check as running before case resolution. That was correct for the service call but wrong for the dependency, so the original 404 assertion is right and the finding is withdrawn. The final API run confirms it.

**Condition 2, lock order.** Confirmed by the helper body. `get_case_and_document_for_update` reads `document_id` with a plain select, then locks the Document row, then locks the ProductionCase row. That is the global Document then ProductionCase order that `generate.py` follows, so the hypothesized deadlock interleaving cannot occur. The retained row lock plus report re-hash stands as the accepted tradeoff.

**Non-blocking observations, no action required:**

- The two 404 branches carry different details, "Case not found" versus "Document not found". An operator can distinguish a nonexistent case from a foreign one by the message. Status parity holds and case existence is low-value, so I leave this to owner judgment.
- The unlocked `document_id` read is safe only while a case's `document_id` is immutable. The forbidden-field list makes that true for operators, and I saw no admin path that changes it. If one is ever added, re-check `case.document_id` after the case lock.
- The multipart test is sound: the spy is restored in `finally`, and the body, both form fields, and the absent JSON content type are asserted directly on the fetch call.

**Scope.** Unchanged from the prior verdict.
