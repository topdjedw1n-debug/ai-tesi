## Висновок і потрібний diff

Повторний реліз попередніх виправлень **не потрібен**. Runtime-код API,
доставлені вихідні файли web, конфігурація запуску та SQL-міграції
відповідають локальному `67ef46deb933b8d88ea8a4f31f3a6a2725412fb4`.
Усі 29 значень release profile збігаються з поточним контрактом.
Необхідні колонки та захисти черги вже є у живій базі.

Для синхронізації продуктового коду з цією версією diff порожній.
Є дві відмінності службових файлів: застарілий `.release-sha` та
`apps/api/.env.example`. Це не доказ старого runtime і не причина
перевипускати вже встановлений застосунок.

Наступний функціональний реліз потрібен після M0-03: числове забезпечення
обох порогів Compilatio та довговічне підтвердження no-rewrite для точного
файла. У M0-06 також потрібно налаштувати запуск служб після reboot,
усунути неоднозначність запису версії та виконати передбачену перевірку
резервування/відновлення. Цей аудит не є дозволом або виконанням релізу.

## 3. Живі HTTPS-перевірки

Використано маршрути та очікування `infra/deploy.sh`, із перевіркою
сертифіката. Запити документів мали навмисно невалідний bearer token:
вони перевіряють маршрутизацію/авторизацію без створення даних.

| Запит | Фактична відповідь |
|---|---|
| `GET /health` | 200. |
| `GET /auth/login`, `/admin/login`, `/dashboard` | 200. Це доступність сторінок, не підтверджений вхід Тані. |
| `GET /auth/register` | 302 → `/auth/login`. |
| `POST /api/v1/auth/magic-link` | 403. |
| `POST /api/v1/documents` | 307 → `https://app.thesica.co/api/v1/documents/`. |
| `POST /api/v1/documents/` | 401, запит доходить до авторизації. |

Колишня помилка HTTPS → HTTP не повторилася. Клієнтські payment/refund
перемикачі web мають значення false. Закриту реєстрацію не змінювали.

## 5. Що залишається до контрольного запуску

1. **M0-02:** підтвердити конкретний обліковий запис Тані, потрібні права,
   доступ до Compilatio та перші придатні замовлення. Наявність сторінок
   і назване ім'я оператора не доводять цих передумов.
2. **M0-03:** забезпечити серверний контракт видачі. Підтверджено в
   поточному коді: `ManualDetectorResultRequest` допускає `result_percent`
   0–100 незалежно від `decision`, а `ProductionCaseService.record_detector_result`
   присвоює `gate.status = data.decision`. Числова планка ≤10/≤10 цим не
   забезпечена; окремого durable no-rewrite підтвердження в моделях немає.
3. **M0-04/M0-05:** перевірити реальні автоматичні джерела і повний шлях
   менеджера. Наявні локальні тести та встановлений код не закривають ці задачі.
4. **M0-06:** випустити тільки потрібні подальші зміни після перевірки,
   включно з restart policy, версіюванням релізу та резервуванням/відновленням.
   Загальний CI лишається червоним; автоматичний деплой зараз пропускається.
5. **M0-07:** зафіксувати оператора, замовлення, фінальну версію й
   авторизований платний M1-запуск.

**M0 загалом не закрито; M1–M3 не доведені.** Нової генерації, записів у
production БД, міграцій, деплою, перезапуску або повідомлень Тані/клієнтам
цей аудит не виконував. Зміни сесії — лише статуси та докази в документах.
