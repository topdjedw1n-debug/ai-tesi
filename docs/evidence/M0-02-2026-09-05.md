## Minimal implementation

- `PRODUCTION_OPERATOR_USER_IDS` defaults to `[]`; activation for the identified
  account is `[1]`. It is separate from Telegram enrollment and quota exemptions.
- Authenticated, active operators can list/create/read/update their own
  production cases, obtain the internal review DOCX, record detector results,
  and request release through the existing artifact/gate services.
- Ownership is checked against `Document.user_id`, including list totals and
  direct case/document IDs. Body-based creation checks ownership before writes.
  Operators cannot assign other users, use admin gate overrides, obtain broad
  document/user/settings access, or grant themselves administration rights.
- Existing admin permission enforcement is retained. New access does not
  bypass missing/changed artifact checks or quality gates, and does not enqueue
  generation when a case is created. No schema migration is needed.
- `/auth/me` exposes a server-derived capability. The ordinary manager cabinet
  provides `Перевірка та видача` at `/dashboard/production-cases` and its own
  detail route. Existing production forms are reused without the admin shell;
  links stay in the manager workspace and manual override actions are hidden.
- Existing inherited English labels, technical gate names and editorial-minute
  displays are not proof of a finished manager UX; M0-05 must resolve these
  against the founder's current no-rewrite product contract.
