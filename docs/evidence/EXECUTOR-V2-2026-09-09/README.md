# Executor v2 — локальне виконання кроків 3 і 4

Чинний обсяг: погоджені SPEC-EXECUTOR-V2 та CONTRACT-CABINET-EXECUTOR з доповненням 1 від 09.09.2026. Реалізація в ізольованій гілці `codex/executor-v2`, база `cf863e9`. Початковий робочий каталог зі сторонніми змінами не змінювався.

## Що реалізовано

- Єдиний виконавець `executor_v2.run(job)`: S1–S6, одна модель у job, записи входів/відповідей/залежностей, заморожений пакет джерел, послідовне збереження розділів, перевірені посилання, DOCX перед дорадчим оглядом.
- Старий `BackgroundJobService.generate_full_document` видалений. Черга викликає v2 без вибору між виконавцями. Сумісний async URL проходить через ту саму чергу.
- Кабінет отримує українські статуси та стопи з API, показує етап, розділи, облік і групи попереджень. Heartbeat старіє й під час недоступності API. Скасування є окремим станом без технічного стопу.
- Підтвердження завдання обов'язкове, також із методичкою. Повторний активний запуск — 409. Нова спроба — новий job; попередні матеріали знімаються в provenance перед заміною. Після дії власника можна повторити також provider_access/internal_error; старий job не змінюється.
- Внутрішнє завантаження читає збережений файл і звіряє SHA. Правила видачі та оцінювання старих робіт збережені.

## Перевірка

- 243 API-тести: [журнал](api-tests.txt). Включно з усіма запобіжниками §8, втратою запису після DOCX, скасуванням під час утримуваної відповіді та новими спробами після дії власника.
- 29 UI-тестів: [журнал](web-tests.txt). TypeScript `tsc --noEmit` — без помилок.
- Пакет: 1500 рядків після Black, 0 перемикачів, 3 дозволені стопи; `internal_error` залишається дефектом. Ruff для пакета проходить.
- 78 тестів видаленого старого виконавця замінені тестами v2; [точний список](retired-executor-tests.txt). Перевірки бібліотек, черги, API та видачі залишені активними.

Дані пошуку, перевірені метадані й тексти взяті з реального запису job12 (прогін №11). Структура S1 і план S3 — синтетичні заготовки; це **офлайн-перевірка механізму**, не доказ живої генерації або академічної якості.

Результат: 6 розділів, 9 заготовлених відповідей моделі, 9 перевірених бібліографічних записів, 22 попередження. Неперевірених внутрішніх маркерів і буквального Markdown у DOCX немає. Переглянуто мініатюру першої сторінки; повне посторінкове візуальне приймання не заявляється.

SHA-256 оригінального DOCX і відтворення в **новій порожній SQLite**, із забороненою мережею:

`e3ba0bc35f128028f284ad1b9a43f030f7b24b2748d642d2709361d0be924ba9`

SHA-256 повного запису після розпакування gzip (дані не скорочені):

`f17e7c71cb6e9be1a72606049ebfe66d2217427bb7bef0f9e630bb277f211f2a`

Окремий CLI: `python scripts/replay_generation.py RECORDING.json.gz NEW_OUTPUT_DIRECTORY` з `apps/api`. Каталог має бути новим; скрипт не використовує зовнішню БД, ключі чи мережу. Неповний запис дає `incomplete`. Звичайний replay стрічки залишається без запису в історичну БД; журналювання спожитих відповідей увімкнене лише в ізольованому CLI.

`profile_changed: true` у replay — порівняння старого профілю з тестовим job, у якому цього legacy-hash не було. v2 не використовує його для вибору поведінки; незмінність промптів перевірена стрічкою, DOCX збігається побайтово.

Тест корпусу пише тільки у `tmp_path`. Цей комплект скопійовано окремо після успішного прогону; наступні тести його не перезаписують.

## Межа приймання

Платних генерацій v2, встановлень, змін живої БД і деплою не було. Використані вже наявні Python/Node-залежності. Крок 4(б) — один живий платний прогін — потребує окремого «так» фаундера. Так само ще не підтверджені жива якість письма, Compilatio і робота менеджера на сервері. Під час подальшого деплою черга має бути порожньою: перервана v2-спроба завершується технічним стопом і потребує нового job.
