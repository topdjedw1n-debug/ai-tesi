## Що змінилось після перевірки

П'ять обов'язкових правок першого раунду внесені до редакції, яку Fable перевірив у другому:

1. Обрана одна модель відновлення: повторне використання того самого job з історією намірів і лімітів. Fable відкликав попередню рекомендацію linked new job після перевірки прив'язок витрат, checkpoint і review.
2. Сервер захищає результати від старого руйнівного POST, включно з manager/admin шляхами. Приховування кнопки в UI було б недостатнім.
3. Узгодження плану не змінює затверджену структуру; реальна негативна оцінка, успішна оцінка та технічна неможливість оцінювання мають різні результати.
4. Сумісність фіксується профілем і перевіряється під час enqueue/resume/claim; перемикання версії відбувається без активних jobs.
5. Конкурентні сценарії виконуються на реальному PostgreSQL. Пропущений тест або SQLite не зараховуються як цей доказ.

Три уточнення фінального раунду також внесені до чинного плану: явний менеджерський шлях «Почати заново» для non-resumable причин із підтвердженням заміни та збереженням історії; тести мапування типових збоїв провайдера замість масового `unknown_failure`; відсутність очікуваних читабельних доказів/`retrieval_trace` класифікується як порушення checkpoint, не академічний FAIL.

## Перевірені поправки до порад

- `SDK max_retries=0` не вимикає прикладний `RetryStrategy`: у плані облік охоплює всі реально ввімкнені шари. Fable визнав цю поправку в другому раунді.
- Невідому помилку не дозволено автоматично відновлювати без класифікації; натомість відомі тимчасові причини повинні мати прямий шлях менеджерського повтору.
- Cancel і resume можуть обидва бути в аудиті як дві послідовні законні дії. Тест перевіряє серіалізацію та кінцевий стан, а не забороняє таку історію.
- Після другого рев'ю Codex перевірив твердження, що чинного maintenance middleware достатньо. У `apps/api/app/middleware/maintenance.py` перевіреного worktree є обхід для admin, дозволених IP, порожнього whitelist та помилки перевірки. Тому S2/S3/T10 і §7 доповнені спільним guard усіх enqueue та окремим способом закриття старих шляхів під час першого встановлення. Це поправка за кодом **після** фінальної відповіді Fable, а не повторно схвалені ним точні байти плану.

Перевірений код: worktree `.scratch/m0-12-m1-q01-20260908/worktree`, HEAD `27f80da9101d4faa3c71122105ed6d387cd65655`; його `apps` відповідають записаній базі `067e90cab8f9dc8f5720cfc6ff3fb948be11b8f9`. Живий runtime цим плануванням не перевірявся. Файли `plan-reviewed.md` є незмінними історичними знімками; виконувати слід чинний план за посиланням угорі.

S0–S5 ще не виконані. Технічна перевірка кандидата не закриває академічний PASS або чинні M1/M2/M3 і не доводить багаторічну безвідмовність.
